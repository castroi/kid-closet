# AI doll look — decisions and implementation plan

Feature for `castroi/kid-closet`. Status: **in progress** (PR 1 `feat/doll-image`). Date: 2026-10-26.

## 1. Goal

In the outfit preview ("לראות את הלוק"), she can press one button and see a doll wearing the outfit, generated by an AI image provider. Results are saved on the phone and reused, so each combination is paid for once.

## 2. Decisions taken

| # | Decision | Notes |
|---|---|---|
| 1 | Photos may leave the phone, **only to the AI provider the parent selected** | Replaces the "photos never leave the device" promise. README and `CLAUDE.md` must say so. |
| 2 | Metadata is stripped before sending | Stored photos are already clean (canvas re-encode). `stripPhotoMetadata()` (`src/image/metadata.ts`) runs again on each image right before upload. |
| 3 | Exactly 3 images per request | No layer: **doll + shirt + trousers**. With a layer: **doll + layer + trousers** (shirt not sent). |
| 4 | A saved look is identified by the images that were sent | Key = `dollId + upperId + bottomId`. With a layer, every shirt under it shares one picture (no extra cost). |
| 5 | Kid gets one try per combination; only the parent regenerates | A failed, refused, timed-out or cancelled call does **not** use up her try. |
| 6 | Providers: Venice and OpenRouter first, generic for more | Each provider is a small code adapter with its address built in. No free-text URL field (the CSP must list fixed hosts). |
| 7 | Settings live in the parent area (behind the question), not in הגדרות | הגדרות stays the kid's theme sheet. |
| 8 | Settings: provider, API key, model, prompt | Prompt is editable, with "חזרה לברירת מחדל". |
| 9 | API key is never in the backup ZIP | Backups go to iCloud and get shared. The key stays on the device only. |
| 10 | Doll image: bundled default, parent can replace or reset | Default = the stylized 11-year-old doll (grey tee and shorts) chosen on 2026-10-26, bundled as `src/assets/doll-default.webp`. Each replacement gets a new `dollId`, so old looks stop matching; the parent is asked whether to delete them. |
| 11 | AI result is saved as WebP | Through the existing pipeline (`processImage`), max side 1024 px for looks (800 px for garments as today); JPEG fallback. |
| 12 | Real garment photos stay visible | Show the AI picture with a row of small real photos under it, plus a toggle "בובה / תמונות". Required by the "she matches real colours" rule. |
| 13 | Changing the prompt does not redo old looks | Each look records which prompt made it. Parent redoes specific looks from a list. |
| 14 | Export | Doll and AI looks are included in the backup and restored with the same validation and size caps. |
| 15 | Monthly cap: **100 images**, counted per device, set in the parent area | Parent regenerations count too. Countdown shown to her only at 20 or fewer; at 0 the button is disabled until the 1st. |
| 16 | The preview **opens on the AI picture** when one exists | The toggle "בובה / תמונות" switches to the real photos. |

## 4. Privacy and security changes

- **CSP** (`vercel.json`): `connect-src 'self' https://api.venice.ai https://openrouter.ai`. Nothing else. `securityHeaders.test.ts` checks the exact list.
- **Adding a provider** = one adapter file + one host in the CSP + its test. That is intentional: a hacked dependency still can't send photos to an arbitrary site.
- **API key storage**: device only (`localStorage`, like the theme), never in `closet.json` or the backup. Shown masked (last 4 characters).
- **Sent data**: only the three images and the prompt. No names, colours or occasions.
- **Recommendation for the parent**: set a spending limit on the provider key itself where the provider supports it (OpenRouter does; Venice unverified).
- **Docs**: README "How data is stored" and the `CLAUDE.md` platform table get the new rules.

## 5. Data model (`SCHEMA_VERSION` 1 → 2)

Old `closet.json` files and backups (v1) must keep loading; they read as v2 with the defaults below.

```ts
interface Doll {
  id: string;            // new id on every replacement; 'default' for the bundled one
  image: string | null;  // 'images/doll-<id>.webp', or null = bundled default
  updatedAt: string;
}

type UpperSlot = 'top' | 'layer';

interface AiLook {
  id: string;
  dollId: string;
  upperId: string;       // shirt, or layer when the outfit has one
  upperSlot: UpperSlot;
  bottomId: string;
  image: string;         // 'images/look-<id>.webp'
  provider: string;      // 'venice' | 'openrouter' | future ids
  model: string;
  promptHash: string;    // which prompt made it
  flagged: boolean;      // kid tapped "לא דומה?"
  createdAt: string;
}

interface AiSettings {   // in closet.json, included in backup (no secrets)
  provider: string | null;
  model: string;
  prompt: string | null; // null = built-in default
  monthlyCap: number;    // default 100
}

interface ClosetData {
  // ...existing fields
  doll: Doll;
  aiLooks: AiLook[];
  ai: AiSettings;
}
```

Device-only (not in backup): API key per provider, monthly usage counter (`{ month: '2026-10', count: n }`).

Rules:
- Lookup key: `${dollId}|${upperId}|${bottomId}`. At most one look per key.
- Deleting a garment (parent area) deletes the looks that use it and their images. "Outgrown" keeps them, because it has undo.
- Replacing the doll asks whether to delete the old looks; if kept, they stay on disk but no longer match. "מחיקת כל תמונות ה־AI" removes them. Deleting never gives uses back.
- Every write goes through `ClosetRepository`, one at a time, as today. Look images follow the existing rule: one file per id, so deleting one look never removes another's picture.

## 6. AI provider layer

### Shared interface

```ts
interface LookRequest {
  doll: Blob;
  upper: Blob;
  bottom: Blob;
  prompt: string;
  model: string;
  apiKey: string;
  signal: AbortSignal;
}

interface AiProvider {
  id: string;              // 'venice', 'openrouter'
  label: string;
  host: string;            // must match the CSP entry
  defaultModel: string;
  generateLook(req: LookRequest): Promise<Blob>;   // returns the raw image
  testConnection(apiKey: string, signal: AbortSignal): Promise<void>;
}
```

Errors are mapped to one type with a reason: `no-key`, `offline`, `unauthorized` (401), `no-credit` (402), `rate-limited` (429), `refused` (content filter), `timeout`, `bad-response`, `cancelled`. The kid sees one friendly line; the parent area shows the reason.

Timeout: 90 seconds, through `AbortController`.

### Venice

- `POST https://api.venice.ai/api/v1/image/multi-edit`, header `Authorization: Bearer <key>`.
- Body: `modelId`, `prompt`, `images` = array of up to 3 (base64 strings, URLs or file uploads). The first image is the base (the doll).
- Response: raw `image/png` bytes. 402 = insufficient balance.
- Docs: https://docs.venice.ai/guides/media/image-editing and https://docs.venice.ai/api-reference/endpoint/image/multi-edit.md

### OpenRouter

- `POST https://openrouter.ai/api/v1/chat/completions`, header `Authorization: Bearer <key>`.
- Body: `model`, `modalities: ["image", "text"]`, one user message whose `content` is the prompt text followed by the three images as `image_url` data URLs, in order doll, upper, bottom.
- Response: base64 data URL in `choices[0].message.images[0].image_url.url`.
- Docs: https://openrouter.ai/docs/guides/overview/multimodal/image-generation
- To verify in PR 3: whether a given model is reachable through chat completions or only through the Image API (`POST /api/v1/images` with `input_references`).

### Default prompt

```
Dress the doll from image 1 in the upper garment from image 2 and the bottom from image 3. Keep the doll exactly unchanged: same face, hair, body, pose, hands, feet, background, lighting, camera angle and framing as image 1. Copy both garments faithfully from their photos: exact colors, fabric texture, pattern, print, logo position, sleeve length, leg length, waistband and drawstrings. Do not change any garment's color, length or cut. Show the fabric smooth, without the wrinkles from the photos. The doll's grey base clothing must be completely hidden. Output only the dressed doll, no text.
```

## 7. Image pipeline

1. Read the three stored images (doll, upper, bottom) from OPFS.
2. Run `stripPhotoMetadata()` on each.
3. Send through the selected adapter.
4. Check the response really is an image (type and size cap).
5. Pass it through `processImage` with max side 1024 → WebP (JPEG fallback).
6. Save `images/look-<id>.webp`, then add the `AiLook` record.

## 8. UX

Reviewed by the UI/UX agent twice (plan and mockup, 2026-10-26). Mockup: the "AI Doll Look Mockup" canvas (7 screens). The mockup hardcodes colours; the code uses tokens only.

**Preview screen (kid)**
- Button **"להלביש את הבובה"** with a sparkle icon, secondary style, below the look, so "לשמור" stays the main action.
- Hidden when no provider/key is set. Disabled offline with the caption "צריך אינטרנט".
- **Countdown, shown only when 20 or fewer are left** (an always-visible number turns the dolls into something to spend). Wording without "לך", because parent regenerations count too: "נשארו עוד 12 בובות החודש"; singular "נשארה עוד בובה אחת החודש". The singular/plural rule lives in one helper next to `src/core/gallery.ts`.
- **At 0:** button disabled, caption "הבובות של החודש נגמרו. חוזרות ב־1 בנובמבר" (real date of the next month). Saved AI looks still show. The parent can still regenerate or raise the cap.
- Waiting: doll shown faded, text "הבובה מתלבשת… זה לוקח עד דקה", an indeterminate animation (no fake percentage), button "ביטול". If the picture arrives after cancel, it is saved anyway (already paid for).
- The request lives in the app's shared state, not in the screen, so leaving the tab doesn't lose it. A toast "הבובה מוכנה · לראות" appears; "לראות" opens that look's preview without changing what she is currently picking.
- Result (opens first when a look exists): AI picture with a permanent tag "תמונת AI · צבעים וגזרה יכולים להיות שונים", a row of small real garment photos under it (**all garments of the outfit**: layer, shirt and trousers when there's a layer), and the toggle "בובה / תמונות".
- After her try: no regenerate button. **"לא דומה?"** (touch target ≥ 44 px) marks the look for the parent and shows "סימנו להורים".
- Error: "לא הצלחנו להלביש את הבובה הפעם. נסי שוב אחר כך." (in `--danger-text`). Her try is not used.

**Favourites ("הלוקים שאהבתי")**
- A card shows the AI look with a small sparkle mark when one exists, otherwise today's photo collage.
- The remove heart stays on every card.
- With a layer, the card adds a small shirt thumbnail, because outfits that differ only by shirt share one AI picture.

**Parent area: short panel "בובה ו־AI"** (between backup and storage), only what's checked often:
1. Status line ("מחובר · נבדק היום" / last error)
2. Usage bar: "23 מתוך 100 · מתאפס ב־1.11"
3. Row "לוקים לתיקון (n)" → its own screen
4. Row "הגדרות AI" → its own screen

**Screen "הגדרות AI"**
1. Provider (two-option switch)
2. API key: shown as masked text (last 4 characters); "החלפה" opens an empty field
3. Model
4. "בדיקת חיבור"
5. Monthly cap (default 100)
6. Doll: "החלפה" / "לבובה הרגילה". Changing the doll asks "למחוק את הלוקים הישנים?" (old looks no longer match and would only take space)
7. Collapsed "מתקדם": prompt text box with "חזרה לברירת מחדל"
8. Last: "מחיקת כל תמונות ה־AI" with their count and size, behind a confirmation sheet like the existing delete flow in `Parent.tsx`. Deleting does not give uses back.

**Screen "לוקים לתיקון"**
- Each marked look next to all its real garment photos, with "ליצור מחדש" / "להשאיר" / "למחוק את התמונה".

**New colour tokens** (light and dark values in `src/styles.css`)
- `--ai`: the sparkle, AI button outline and usage bar (instead of reusing `--focus`).
- `--ok`: the "connected" status dot.
- Badges on photos use `--surface`, never a hardcoded white.

All existing UX rules apply: Hebrew RTL, touch targets ≥ 44 px, colours only through tokens, garment photos never dimmed.

## 10. Tests

Coverage thresholds stay: 80 % lines/statements/functions, 75 % branches. Run `npm run lint`, `npm run typecheck`, `npm run test:coverage` before every push.

**Core (`src/core`)**
- v1 `closet.json` loads as v2 with default doll, empty looks, default AI settings.
- Look key: shirt sent when no layer, layer sent when present; same picture reused for different shirts under one layer.
- Changing the doll stops old looks from matching.
- Deleting a garment removes its looks; "outgrown" keeps them.
- Validation rejects malformed looks, unknown providers, bad image paths.

**Providers (fake `fetch`)**
- Venice: request URL, headers, `modelId`, `prompt`, three images in order doll, upper, bottom; PNG response returned as a Blob.
- OpenRouter: request body shape, `modalities`, image order; data URL parsed into a Blob.
- Each error: 401, 402, 429, content refusal, non-image response, timeout, cancel → the right reason.
- API key never appears in errors or logs.

**Image pipeline**
- `stripPhotoMetadata()` is called on all three images before sending.
- Result goes through `processImage` with max side 1024 and is saved as WebP (JPEG fallback path too).
- Oversized or non-image response is rejected.

**Storage and backup**
- Look image path is always `images/look-<id>.<ext>`; deleting one look never removes another's file.
- Backup contains the doll and looks but **not** the API key or usage counter.
- Restore validates, unpacks only known files, applies size caps, and still restores old v1 backups.

**UI (Testing Library)**
- Button hidden without key, disabled offline, blocked at the cap with the next reset date.
- Countdown hidden above 20, shown at 20 and below, singular at 1; parent regenerations lower it.
- Waiting state and cancel; result after cancel is still saved.
- A failed call leaves her try; a successful one removes the button for that combination.
- Leaving the tab during a request: result saved, toast shown.
- Toggle "בובה / תמונות", AI tag, real-photo row (shirt included with a layer).
- "לא דומה?" marks the look; parent list shows it with regenerate/delete/keep.
- Parent panel: key masked, prompt reset, test connection success/failure.

**Security**
- `securityHeaders.test.ts`: `connect-src` lists exactly `'self'`, the Venice host and the OpenRouter host.

**Manual, on her iPhone (PR 3 and PR 4)**
- Real call through each provider from the home-screen app (CORS).
- Real result quality with the default doll and her own photos.
- Offline behaviour and leaving the screen mid-request.

## 12. Risks

| Risk | Mitigation |
|---|---|
| Venice blocks browser calls | Test first in PR 3; fall back to OpenRouter only, or decide on a small proxy |
| AI changes colours or cut | Real photos always visible; AI tag; "לא דומה?" flow |
| Content filters refuse the realistic child doll | Mapped to the `refused` reason; parent can switch to a more stylized doll |
| Unexpected cost | Monthly cap in the app plus a limit on the provider key |
| Key on the kid's phone | Behind the parent question, masked, never exported; spending limit on the key |
| Storage growth | Looks at ≤1024 px WebP; delete-all button with size shown |
