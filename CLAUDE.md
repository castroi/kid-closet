# kid-closet — project rules

Outfit picker for one 11-year-old on her iPhone. Static PWA on Vercel; no server, no database.

## Git workflow

- Every change gets its own branch from `main`, named `<type>/<short-description>` (`feat`, `fix`, `chore`, `docs`, `test`). Why: `main` is what Vercel deploys.
- Never commit directly to `main`; push the branch and open a pull request. Only the owner merges, after CI is green.
- Run `npm run lint`, `npm run typecheck` and `npm run test:coverage` before pushing.
- Commit `package-lock.json` with every dependency change. If `npm install` can't run locally, just push the `package.json` change to your branch: the "Update version and lockfile" workflow commits the lockfile there by itself and reruns CI (never on `main`).
- A code review agent reviews every pull request before it is merged, on the pull request itself, so the review stays in the PR's history:
  1. Push the branch and open the pull request as a **draft**. CI runs while the review happens.
  2. The review agent reads the PR diff and posts its verdict and findings as a GitHub review (line comments where they help). When it posts with the PR author's token, the review must be a comment review with the verdict in its text, because GitHub doesn't let authors approve their own PR.
  3. Fix findings as new commits on the branch. Never force-push, so the history shows how each finding was answered; if the branch falls behind `main`, merge `main` into it instead of rebasing. Then post one PR comment that lists every finding with the commit that fixed it, or why it is left to the owner.
  4. The review agent checks the fix commits and posts a short follow-up review. When CI is green and that follow-up confirms every finding is fixed or listed as left to the owner, mark the PR ready for review. Only the owner merges.
- One review agent can review a series of PRs in a row, keeping its project context, but each PR gets its own review.
- Every PR has the version its branch type needs, against `main`: `feat/` → next minor (or a deliberate next major), `fix/` → next patch, `chore/`, `docs/`, `test/` → unchanged or next patch. Nobody has to set it: on every push to a branch, the "Update version and lockfile" workflow (`.github/workflows/update-lockfile.yml`) runs `scripts/version-check.mjs --bump` against `main` as it is at that moment, keeps a version that's already right, otherwise sets it in `package.json` and both fields of `package-lock.json`, commits that to the branch and reruns CI. It waits until the branch contains `main` (bumping past a `main` the branch hasn't merged would make the version lines conflict). Locally the same is `git fetch origin main` then `npm run version:bump`. If it committed, pull before pushing again. If the version lines conflict anyway, take `main`'s version in both files and push; the workflow sets the right one. It runs `npm install --package-lock-only` only when the lockfile doesn't already list `package.json`'s dependencies. CI checks the version with the same script on every branch run, and on `main` after each merge (red if two PRs took the same version). If `main` moves on while a PR is open, GitHub's "Update branch" button (or merging `main`) bumps it again; the repository setting "Require branches to be up to date before merging" makes GitHub insist on that. Why: the version is decided on the PR branch, where it's reviewed, never by a bot pushing to `main`; one script and one set of rules, so the bump and the check can't disagree.

## Platform decisions

| Rule | Why |
|---|---|
| Data is plain files in OPFS: `closet-a.json` / `closet-b.json` written alternately with a rising `generation`, photos in `images/<id>.webp` (`.jpg` fallback) | Runs fully on the phone; an interrupted save never loses the previous version |
| Always save above the highest generation on disk, even one that can't be read | A newer app version's data is never outranked by mistake |
| An item's photo is always `images/<id>.<ext>` | Deleting one item can never remove another's photo |
| If the closet files exist but can't be read, show the recovery screen; never start empty over them | No silent data loss |
| If the phone refuses storage access (e.g. a Safari private tab, `UnknownError`), say so and offer a retry; never call it corruption | Private tabs have no usable storage; a false "files are damaged" message scares the parent |
| Writes go through `ClosetRepository`, one at a time | Saves never interleave |
| Photos: resize to ≤800 px on the phone, WebP via `@jsquash/webp`, JPEG if that fails | Safari can't encode WebP itself |
| Backup = one ZIP (`closet.json` + photos); restore validates everything, unpacks only known files, caps sizes | The only copy that survives removing the app |
| Hebrew, right to left; touch targets ≥ 44 px | It's for the kid |
| Theme: "כמו בטלפון" (follows the phone, default) / בהיר / כהה, chosen by her in הגדרות (gear next to the lock in the closet screen), saved per device in localStorage (`src/app/theme.ts`), never in the closet or backups | It's her preference and belongs to the device; the dress-up screen keeps its 3 decisions |
| Colours only through the tokens in `src/styles.css`; text on an `--ink` fill uses `--on-ink`; accent/danger as text use `--accent-text` / `--danger-text` | Both themes keep readable contrast |
| The inline script in `index.html` applies the theme before paint and must match `applyTheme()` (key, colours). Its SHA-256 is allowed in the CSP in `vercel.json`; update it whenever the script changes (`securityHeaders.test.ts` fails until you do) | No flash of the wrong theme; the CSP blocks any other inline script |
| Security headers for every page live in `vercel.json` (CSP, nosniff, no referrer, no framing, HSTS). The CSP allows only this site's own files, `blob:` images, WebAssembly for the WebP encoder, and `connect-src` to exactly the AI providers' endpoint URLs in `src/ai/catalog.ts` (one for a look, one for the key check; `securityHeaders.test.ts` checks the list matches) | Even a compromised dependency can't load outside code or send photos anywhere but these endpoints (all stay open; the app itself sends only to the provider the parent picked) |
| `.npmrc` sets `ignore-scripts=true`; dependencies don't run install scripts locally, in CI or on Vercel | A hijacked package version can't run code during install |
| Libraries that ship inside the app (every entry in `dependencies`: `@jsquash/webp`, `fflate`, `react`, `react-dom`) are pinned to exact versions; update them deliberately in their own PR. GitHub Actions are pinned to full commit SHAs with the version in a comment | The lockfile workflow can't silently pull a newer, possibly hijacked release into the app; a moved tag can't change what CI runs |
| Garment photos are never filtered or dimmed in dark mode | She matches real colours |
| Each dress-up row has "סוג וצבע" (filter; when on, the button turns dark and shows it) and "גלריה" (a 2-column grid of that row, also opened by a tap on the photo but not after a swipe). Picking in the gallery selects and closes; nothing else changes | Seeing everything at once without leaving the dress-up screen; "הארון שלי" stays for managing clothes, where a tap means "edit" |
| One filter per row, shared by the arrows, "סוג וצבע" and the gallery. The gallery keeps it, titles what's shown with Hebrew agreement ("חולצות כחולות", "מכנסיים כחולים", `src/core/gallery.ts`), shows "3 מתוך 8", and clears it in one tap or with "להציג את כל 8 החולצות". Changing a filter keeps the garment she was looking at when it still fits | She said "blue" — a bigger view must not undo that; a label like "הכל" would lie when a filter is on |
| Delete only in the parent area (behind a question); the kid has "outgrown" with undo | Safe from accidental taps |
| The parent area shows "גרסה 1.4.0 · a1b2c3d": the version from `package.json` and the commit, set at build time from Vercel's or GitHub's commit SHA (`vite.config.ts`, `src/app/buildInfo.ts`). The commit links to it on GitHub, plus a link to the repository. No build dates | You can tell exactly which build is on her phone; the same commit always builds the same app |
| Bump `SCHEMA_VERSION` when `closet.json` changes shape, and keep reading old versions | Saved closets and backups keep working |
| The doll for AI looks: the bundled `src/assets/doll-default.webp` (id `default`) until the parent replaces it in the parent area. Her picture is `images/doll-<id>.<ext>` (≤1024 px), with a new id on every replacement; the old picture is deleted after the save. It is in backups. The build fails if the default doll isn't a cached file | The id tells which doll an AI look was made with; a data: URL would be blocked by the CSP and not work offline |
| The AI doll look feature is planned in `docs/ai-doll-look.md`; follow its decisions | One place for what was agreed with the owner |
| Provider calls go through `src/ai/send.ts` only: it strips photo metadata, applies the timeout, and checks the answer is a picture; `src/ai/providers.ts` has one small adapter per provider and maps failures to `AiError` reasons. The kid never sees provider messages; the parent area does (`src/ui/aiErrors.ts`) | One place enforces privacy and limits; a new provider only describes its request and response |
| AI looks (`aiLooks` in `closet.json`, pictures `images/look-<id>.<ext>`, ≤1024 px WebP, or the provider's WebP/JPEG as it came when the phone can't decode it) are keyed by what was sent: doll id + upper garment (the layer when there is one, else the shirt) + trousers. Requests run in `src/app/AiLooks.tsx` above the screens, so leaving the screen doesn't lose a paid picture; her "ביטול" only stops waiting. Deleting a garment deletes its looks. Backups include them newest first while the backup stays within the restore limits; the oldest (and any whose picture is lost or over the per-file limit) are left out and the parent is told (`src/storage/backup.ts`). Clothes and the doll always go in | A picture is paid for once; a look made for one shirt under a jacket fits every shirt under it; a backup that can't be restored would protect nothing |
| AI settings (provider, model, prompt, monthly cap) are in `closet.json` and backups; the API keys and this month's use are only in the phone's localStorage (`src/app/aiDevice.ts`), never in the closet or backups. The settings live in the parent area ("הגדרות AI"), never in her הגדרות | Backups go to iCloud and get shared; a key costs money |
| `/sw.js` is generated at build time (`src/sw/serviceWorkerSource.ts`, wired in `vite.config.ts`): it pre-caches the app shell plus every file of that build in a cache named after the build's files and the worker's logic, deletes older builds' caches, shows the cached page after 3 s on a weak signal, and never calls `skipWaiting`. The build fails if the file worker or the WebP `.wasm` is missing from the list. Never add a hand-written `public/sw.js` | The app works fully offline, including the file worker and the WebP encoder; a running old version never loses files it still needs |
